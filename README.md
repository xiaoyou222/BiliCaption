# BiliCaption

Chrome 扩展：在 B 站、YouTube 普通视频和 X 视频帖子中，用侧边栏看字幕、翻译、划选总结、大纲和标记。

不在 Chrome 网上应用店上架。请用开发者模式加载解压后的文件夹，**不要**把 `.crx` 拖进扩展页（会被拦截）。

## 安装

需要 Chrome 116 或更高版本。

### 1. 下载

任选一种：

- **推荐**：打开 [Releases](https://github.com/xiaoyou222/BiliCaption/releases)，下载最新的 `BiliCaption-*.zip`，解压
- 或点仓库绿色 **Code → Download ZIP**，解压后得到整个仓库（体积更大，含开发文件）

### 2. 加载扩展

1. 地址栏打开 `chrome://extensions`
2. 右上角打开 **开发者模式**
3. 点 **加载已解压的扩展程序**
4. 选中含 `manifest.json` 的那一层文件夹  
   （Release 压缩包解压后就是这一层；完整仓库则是仓库根目录）

装好后，刷新视频网页，点工具栏里的 BiliCaption 图标打开侧边栏。新增平台权限需要重新加载扩展后才生效。

### 3. 填自己的 API Key

生成字幕、翻译、总结、大纲要用你自己的转写 / 对话模型 Key（例如 Groq、OpenAI、DeepSeek）。

侧边栏点 **设置**：

- **转写服务**：没有官方字幕时，把音频转成字幕
- **总结服务**：划选总结、大纲、润色

密钥只存在你这台电脑的 Chrome 里，不会进这个仓库。没配 Key 也能看视频自带的 CC 字幕。

## 更新

再下载一份新压缩包，解压覆盖原来的文件夹，然后到 `chrome://extensions` 点扩展卡片上的刷新。不要删掉旧扩展再重装，否则设置和本地字幕缓存会丢。

## 能做什么

- 读取视频自带字幕；没有字幕时用转写生成
- 翻译成中文，侧边栏切换 中 / EN
- 划选一段字幕：总结、复制、循环播放
- 生成大纲和全片总结
- 评估视频是否值得看：已有有效评分直接显示，没有有效评分时点“评估”才请求模型；打开视频、切换页面或刷新字幕不会自动发起评估
- 字幕助手：围绕当前视频继续追问；每个视频及分 P 独立保存对话，关闭侧栏或浏览器后可恢复
- 总结网页文章与博文，按章节查看要点，点击来源跳转并高亮原文；支持手动选择正文、复制和下载 Markdown
- 给当前时间打标记；进度条上会有金色竖线
- 浮窗字幕、倍速；记住最后通过插件菜单或快捷键选择的速度，刷新页面、打开新视频时自动应用
- 可选 WebDAV，在多台电脑之间同步标记和偏好（不同步 API Key，除非你在设置里打开）；转写生成和改过字的字幕也可备份，打开视频时按需下载

## 说明

- B 站：保留原有字幕读取、无字幕转写及分 P 支持。
- YouTube：支持 `/watch?v=…` 普通视频的人工/自动字幕；无原生中文且 YouTube 声明支持翻译时，默认读取 YouTube 自动翻译中文，保留中 / EN 切换。这一字幕轨不调用用户配置的大模型。支持翻译、大纲、总结和播放器联动；暂不支持 Shorts、正在直播的视频和无字幕音频转写。
- X / Twitter：支持普通帖子及 `/video/1` 等视频详情链接。先播放视频，让扩展获取当前视频的字幕播放列表；读取完整 VOD 字幕，不把播放器缓冲中的少量字幕当成全片。多视频按正在播放的视频或链接中的序号区分。
- 新平台若未返回字幕，会明确提示刷新或读取失败，不会自动发起收费转写。YouTube 某些会话会返回空字幕，可先开启网页播放器字幕再点侧栏刷新；仍失败时以提示为准。
- X 导出的时间链接需要本扩展才能定位到对应秒数。标记库和 WebDAV 保留旧 B 站数据，新增平台使用独立编号。
- 仅监听 YouTube 字幕和 X 媒体播放列表请求地址，用于读取当前视频字幕；临时地址存于浏览器会话，关闭标签页后清除，不同步到 WebDAV。
- 生成、翻译、总结和评估会把对应音频、字幕或已识别的文章正文发给你配置的服务商，请用自己的账号、注意用量
- 本仓库源码可自行查看；使用中的问题可以开 [Issues](https://github.com/xiaoyou222/BiliCaption/issues)

## 字幕助手与对话记录

- 按视频和分 P 自动保存在本机，关闭侧栏、刷新页面或重启浏览器后，打开同一视频可继续追问。不按天过期，也不再只保留最近 30 轮。
- 对话记录不参与 WebDAV 同步，清理字幕或文章总结缓存不会删除它。助手内的「清空」只清当前视频；设置 → 数据同步 → 对话记录，可清空本机全部对话。
- 保存记录和模型上下文分开：每次提问仍只带最近 6 轮有效问答，历史部分最多约 8,000 字符，不会把全部旧对话发送给模型。
- 首次读取时自动迁移尚存的旧版临时对话。流式回答定期保存中断快照；关闭助手后保留已收到的内容，并标注「已中断」。

## 文章总结

在普通文章网页上打开插件侧栏，点击「总结文章」。首次读取网站时按浏览器提示授权；打开侧栏本身不会发起总结。

- X 帖子的类型未确认时显示「正在识别页面内容」，页面出现文章标识或正文后立即分类；等待期间不进入视频字幕流程，也不调用模型。
- 用 Defuddle 在本地提取正文，过滤导航、推荐等页面元素，再发送正文给总结服务。默认按 200k token 的单次输入预算优先整篇总结，预算包含提示词、段落编号和小节信息；超预算才完整分段并汇总。若接口明确报告正文输入超限，会自动缩小分段，保留已完成结果；普通超时、限流不会触发拆分。实际容量取决于所选模型与接口，200k 是输入预算，不是字数或输出上限。
- 每条要点的「查看原文」按原文小节合并入口，同一小节内的多段依据只显示一个入口，跨小节才展开列表。点击后定位到第一处引用，以一个连续高亮框覆盖本次引用的首尾位置，包含中间的小标题和空白，只显示一个小节标签；内部保留精确的引用编号。无法可靠对应原网页的来源不生成跳转按钮。
- 识别不完整时，可先在网页展开全文后重新读取，或手动点击正文首尾选择范围。按当前范围总结时会明确标记范围。
- 网页变化或重复段落无法区分时，定位会提示失败；重新读取可更新总结。复制与下载含文章链接及浏览器文本定位链接，外部浏览器是否能定位取决于其支持情况与网页内容是否变化。
- 只处理当前已加载的文字，不自动读取未加载、跨页或图片里的正文。识别结果不能证明已覆盖完整文章。总结保存在本机，再次打开同一文章可复用；已授权的页面会核对正文是否更新，手动选择范围的总结需自行确认。旧缓存会按数量和占用上限自动清理。

## 开发

- 运行扩展无需构建；测试依赖先执行 `npm ci` 安装。改完直接在 `chrome://extensions` 里刷新扩展。
- 跑测试：`npm test`，等同 `node --test tests/*.test.js`。新版 Node 下必须带上 `*.test.js` 这个通配。
- 打包：`scripts/package.sh`（需要 python3），只收运行时文件，生成 `BiliCaption-<版本号>.zip`；`scripts/package.sh --列出` 只看会打进哪些文件。
- 代码按加载点分目录：后台是 `background.js` + `background/`（由 `importScripts` 依次加载），侧栏是 `sidepanel.js` + `sidepanel/`（`sidepanel.html` 里的 script 标签），内容脚本是 `content/` + `content.js`（`manifest.json` 的 `content_scripts`，与 `lib/video-platforms.js` 里的 `CONTENT_SCRIPT_FILES` 保持一致）。这些都是共享全局作用域的普通脚本，新增文件要加到对应的加载点。
- `tests/` 放自动化测试，`tests/fixtures/` 放测试样本，`docs/` 放当前规则和复测记录，`design/` 放设计源。这些开发资料不进入扩展安装包。
- 目录、功能模块和测试文件名统一使用小写英文 `kebab-case`；界面文案、注释和运行提示继续使用中文。

文章内容脚本按点击动态注入，清单在 `lib/article.js` 的 `CONTENT_FILES`；随包包含 Defuddle 0.19.4 和 MIT 许可证。`tests/article-summary.test.js` 使用真实 Defuddle 与 DOM 夹具验证提取、定位和手选；侧栏模型交互使用模拟响应测试取消、重试与导出。
